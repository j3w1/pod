# Cleanup

Follow the host's current cleanup authority and the requested scope. A released-worker plan needs no sweep. When the requested work includes delivery recovery, run `pod sweep --repository PATH --json`, adding `--objective NAME` for a single objective; do not turn worker cleanup into a repository-wide sweep. Repeat `--repository PATH` only for repositories within the requested scope; Pod has no host registry and otherwise defaults to the current repository. To inspect proof without writing, use `pod status --list --delivered --json`; the plain list reads records only.

The sweep closes every proved delivered objective whose coordinator is gone, tails before predecessors, each with its own immutable evidence closure. It reports `closed`, `already_closed`, `not_proved`, `unverified` or `skipped` with conditions. `closed` includes a predecessor whose entry this run wrote; `already_closed` means the closure already existed and nothing was written for it. Once every entry exists, a repeated run writes nothing; a run after an interrupted closure writes only the missing predecessor entries, once each predecessor's own Runs and work read settled, and reports them `closed`; while one is held, it writes nothing and reports the tail `not_proved` with that condition, a task for the project lead. A repository whose records the sweep could not all read is `incomplete`, with a reason naming them: treat its objectives as possibly still open. Unproved lost work stays open for the project lead, never an owner question. A completed sweep exits zero whatever it found; invocation or scope errors exit nonzero. Read the result before the cleanup plan. Closure changes only Pod's reservation; it grants no deletion authority.

`internal cleanup-plan` is read-only and objective-scoped: it shows integrated, merged remote head, unique/protected resources, dirty data, stashes, other worktrees, refs and terminals. For an older record closed by evidence it reads `record_class: older` and keeps protected every resource that depends on a field older records do not document. An older-record worker selector refuses `cleanup_worker_unavailable`; use its protected objective plan without inventing missing admission or report evidence.

One plan is bounded to 96 objective resources; unrelated repository worktrees do not consume that bound. Shared-branch checks still observe every checkout, however large the inventory.

After recording a worker or reviewer report and explicitly releasing it through Orca, request its cleanup while the objective remains open: include `worker: {"admission": "EXACT_ADMISSION"}` or `worker: {"dispatch": "EXACT_DISPATCH"}` in the cleanup-plan input with `project` and `objective`. The result names only that placement, its local branch and matching Governor-published remote branches. Native readback must prove the exact assignment, terminal identity, settlement, release and process exit; missing or contradictory facts hold cleanup. The objective integration worktree stays protected. For a reused placement, select its final released round: earlier assignments need positive release proof or an exact recorded transfer chain into that released resource; an older reused round or another assignment still holding the placement remains protected. This is a lifecycle-triggered request, never a bulk or automatic cleanup pass. Execute the plan through the host's current cleanup authority and engine.

For immediate next-round reuse, add the exact nonempty `reuse_reason` (up to 512 characters) inside `worker`, and save the returned plan as evidence. It records the reason and holds every selected resource. Native retention reasons and known reuse are also reported as holds. No Pod lifecycle record is created by this read. Worker identity, report/release observations and reuse reason participate in `expect`; keep the same selection and reason when rechecking.

Obtain one batched confirmation for the exact deletion classes; an applicable exact-scope instruction counts. Retain unique work, verify an archive bundle before deleting refs, or obtain separate discard consent.

While yolo is active, the cleanup plan's `standing_authorization` fields `covers` and `asks` are the applicable exact-scope instruction. Covered classes need no further owner confirmation; asks still require it. Use the fresh plan for the actual resources, preserving the same guards below.

Rerun with `expect` immediately before deletion; changed facts stop cleanup. Execute only listed guarded Orca/Git commands with exact ref tips and remote leases. Never add `--force` or delete a directory directly. Protected/uncertain resources stay. Native settlement and Delivery acknowledgment follow Orca; worker release follows the explicit coordinator step in the worker-tab guidance.
