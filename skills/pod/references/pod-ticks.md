# Proving and ticking the bound PES

Use this workflow when a tick or untick becomes due, when confirming a tick's readback, or before closing an issue-bound objective. A direct objective has no PoD ticks. Only the objective's bound PES issue is writable; a parent issue, SEAL and EEL are outside this operation.

The introducing checkpoint reports unmapped lines, multiply mapped lines, duplicated numbers and criteria naming missing lines. A live criterion maps by the initial `PoD#N` of its source reference, including the exact reference `PoD#1`, or by its current kernel-owned derived association. Withdrawn criteria, including superseded rows retained as withdrawn, leave the live mapping while their original history stays visible. A line is proven only with a nonempty mapping whose every criterion is satisfied with current evidence. Withdrawal does not prove a criterion. If line facts could not be read, do not infer that there is nothing to tick.

For the supported spelling repair, read `internal contract` for checkpoint and mapping repair, then use an ordinary checkpoint with next `seq` and `mapping_repair: {original_body: BODY, targets: {CRITERION_ID: "PoD#N"}}`. BODY is the unchanged original issue body as DATA, at most 512 KiB UTF-8; name 1–64 existing criterion IDs. Preserve the original objective, IDs, criteria, source.ref, checks and evidence. Bind the current issue through the existing intake/reconciliation route. Pod independently looks up the original kernel checkpoint or accepted native admission binding, hashes the DATA and reads the actual current issue. Supply no digest, approval, verifier or proof assertion. Report and admission maps cannot perform this repair.

Only column-zero, recognized checkbox labels outside fences may change from explicit `PoD N:` to `PoD#N:` with the same textual number; source.ref must begin with that original spelling. Checkbox bytes, line endings, check/requirement prose and every other body byte must remain identical. Each target needs a unique line and live mapping. The derived association preserves original source.ref and adds no proof, consent, Governor or native effect. Exact association restatement is allowed; callers cannot create or change it.

Unavailable, ambiguous or conflicting original bindings hold the repair. Retained PASS without a real proof-time source binding holds `proof_binding_unavailable`, even after its selected evidence is omitted or the row is made unsatisfied. Preserve all receipts and report the hold; a caller assertion, owner decision or restored body does not supply missing original facts. Use genuinely supported source reconciliation for available facts and leave unavailable proof incomplete. New proof after repair still follows the ordinary evidence rules. An observed definition, scope, issue or amendment change permanently retires the derived association; restoring old bytes cannot revive it or stale PASS. Confirmed own checkbox writes retain it through the existing protocol; ambiguous writes establish no proof. Own ticks still require unticking when the last live mapping is lost.

Checkpoint and report acknowledgements name due ticks and unticks with their exact `pod internal pod-tick` requests. Run those requests as the recorded coordinator. Direction is computed by Pod, never supplied by the caller. Pod removes only its own confirmed ticks after proof is lost, including withdrawal or the loss of the last mapping. It leaves ticks by other actors and ambiguous ticks alone.

Each request immediately rechecks the issue, amendments, role and OPEN state, checks the bound body digest and unique line, records an intent, then sends at most one write changing exactly one checkbox character. It records the held response, reads back, and atomically records the receipt with the new bound digest. A successful response plus matching readback establishes Pod's own tick. The rebind changes no map sequence, obligation or evidence. A pre-tick packet must be frozen again before a new admission. A reserved or uncertain admission must first be settled or replayed with its original packet; `pod_tick_admission_pending` names it. This wait never exempts a due tick from closure.

Confirm each returned readback: the receipt names the PoD, direction, old and intended digests, held result, observed digest and checkbox, authorship and rebind. A matching checkbox alone is not proof Pod wrote it. A lost response or interrupted request is recovered by reading back before any new send. An intent still within its send timeout plus five seconds refuses `pod_tick_pending` as in flight; its message and detail name intent_at and retry_after in Unix seconds. Status shows those same times and says the request is in flight until retry_after. Recover at or after retry_after; a clock set back safely keeps the hold until then. An intended body with no held success response produces ambiguous authorship; Pod may bind that body but never claims the tick. A held success for that same request establishes Pod's own authorship even after its ambiguous recovery. An ambiguous untick leaves the line unticked. A held refusal followed by any changed body is an outside edit, even if it matches the intended body. Never retry blindly.

On `issue_reconciliation_required`, use the existing issue reconciliation and checkpoint rebind route. The tick request never reconciles intent. If the issue closes (B3), an amendment or role changes (B2), or an unreadable amendment (B5) holds the readback during the send, matching intended readback still records its own or ambiguous rebind. The hold remains on the request and in status as a separate code and reason; the line keeps its R10 status. A tick stays current and ticked by Pod for held success, ambiguous otherwise; an untick keeps its resulting R10 status. A pre-send refusal also leaves a line that is not due at its R10 status. A CLOSED issue stays blocked after reconciliation and rebind until it is reopened outside Pod and passes the recheck. Unreadable issues, duplicate lines, repository mismatches and GitHub's held write refusals are reported with their reasons. A later request runs the whole protocol and replaces the earlier block. An observed unticked line ends Pod's earlier authorship.

If closure refuses with `pod_ticks_due`, record the same proof without closing, run every due tick or untick and confirm each readback, then close. Both checkpoint closure and report closure use the proposed map's proof. A lost response that left the old body still needs a new request. A block exempts a due tick only if its latest request followed the latest checkpoint or report and stopped on a source hold, unreadable issue, duplicate line, or held GitHub refusal with the bound body unchanged. Closing names each such limitation with its direction, code, reason and last observed checkbox. Also settle any worker tabs named by the refusal.

GitHub has no conditional issue update. An outside edit between Pod's immediate read and its write can be overwritten; a later matching readback cannot reveal that race. Reading immediately before the write narrows this residual race and does not eliminate it.

The final report lists each PoD's last observed tick state against its mapped criteria, every tick without Pod proof, every ambiguous tick, and every due tick or untick that closure left blocked, with its code, reason and readback, including GitHub's refusal. Never count a blocked or ambiguous tick as ticked by Pod. Status reads these recorded facts without fetching; an unavailable kernel view leaves tick proof unavailable, with no inferred direction or due request. Closure preserves blocked limitations and forbids further ticks.
