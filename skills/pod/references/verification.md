# Proof

Bind proof to obligation, final candidate, sources, policy, dependencies, environment, command, time and reviewer attempt. Declare non-assurance `proof_scope` at intake; assurance uses reviewed scope. Candidate movement requires explicit `reuse: {from, ids}` for unaffected obligations with Git delta rechecked at later moves. Changed bindings reopen proof; project rules govern reuse, preferences do not change Governor candidates.

Substantial/risky work requires independent-review assurance. Retain required audits through checkpoint/report/delivery; unavailable review remains incomplete. Only scoped user waiver or genuine trusted-requirement removal permits policy withdrawal; waiver never passes review. Fresh independent reviewers receive exact candidate and reproducible evidence without priming.

Triage required corrections versus advisory proposals. Each new required finding's `blocks` names the outcome, requirement, PoD or standing safety/privacy/account policy it prevents, and its summary explains why. Ask the reviewer for a missing link before considering advisory triage; label substantive safety/privacy findings `policy:safety` or `policy:privacy`, never downgrade them for a missing label. Unlinked findings stay advisory and create proposals; advisories carry no `blocks`. Major/blocker downgrades need reasons. Retain findings and consolidate corrections. Changed scope, assumptions, dependencies, governance or unknown impact requires affected-scope delta review; explicitly REUSE unaffected proof under project rules. Refuse repeat review of valid bindings. Zero/all-withdrawn assurances withhold the review label.

Review packets' report contracts require the link and causal summary for each required finding and a reuse statement for every requirement in scope: installed feature, newer upstream feature, small glue, or new mechanism with a reason. An unjustified new mechanism is required correction when it contradicts the objective's stated reuse requirements; otherwise advisory. Keep these in existing summaries/report text, with no new classification system.

Three review admissions are allowed per objective, including reservations and unresolved starts across candidate changes and R105 handoffs. An R110 successor objective starts its own count. After the last granted round settles and its report is consumed, unfinished correction or assurance means no next review: checkpoint the deterministic owner-only allowance question. Pod adds it even if omitted and deduplicates repeats. A running third round waits without a question; a clean third finishes normally. Read the derived `review_allowance` in report/status; it grants no authority.

Only an owner answer typed in the coordinator's own tab counts. The question has no tappable choices because relayed card replies cannot authorize it. Answer through checkpoint `revision_authority`, naming its recorded `question`, `provenance: user_direct`, `channel: session`, required `instruction` containing the owner's answer, and `allowance`. Use `{choice: continue, rounds: N}` for 1..8 more rounds, `{choice: simplify}` with a same-write named owner-authorized withdrawal or revision for exactly one verification round, or `{choice: stop}` to report incomplete with every unfinished obligation. Grants start from the rounds already used when answering: R+N for continue N, R+1 for simplify, even if an earlier version admitted more than three rounds. The question id uses the rounds used; its text states both used and granted counts. Repaired corrections still require verification; exhaustion asks again if assurance remains open. Silence, relayed answers (even verified) and delegated/responder answers authorize nothing. Answers remain in revision history and resolved question rows; stop satisfies no obligation.

For each required-correction cycle, complete these steps in order:

1. Consume the fixer's report.
2. Satisfy the correction with its proof.
3. Admit the verifying review.
4. Consume the review with the assurance waiting.
5. Satisfy the assurance with that review attempt.

An unresolved required finding refuses review admission as `review_precedes_resolution` and names its correction. Older premature review evidence is invalidated as `ordering`, with the finding's resolution sequence and the attempt's admission and report sequences; it needs a fresh review after correction resolution.

Reports join packet, admission and native attempt; Git supplies changed paths. Short non-assurance proof names check, command, result and reference; settled served assurance may use its attempt. Report obligation provenance, withdrawals, blocks, proposals, boundary exceedances, triage downgrades and remaining gates. Only an authorized revision through the supported decision boundary reopens ordinary coordinator closure; evidence closure is immutable and refuses every Pod write. Synthetic proof never certifies live behavior; unobserved usage/cost stays unknown, never inferred from model labels/counts.

For composite model rules, record the assurance's typed `audit_role` before admission and verify it against the served work using the router's model guidance. A requested coordinator arrangement needs actual supported effective-route evidence; unavailable native evidence stays UNAVAILABLE, and a preview is not proof. Decision authority never supplies review truth or accepts a worker result.
