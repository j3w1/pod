# Verification and reporting

Bind each result to its criterion, candidate, source identity, policy revision,
dependencies, environment, command, time and reviewer attempt. Changed bindings
invalidate affected proof. Reuse unaffected evidence only when project rules
permit it.

Use project-defined checks and review requirements. For substantial or high-risk
work, give an independent reviewer the exact candidate and reproducible evidence
without presupposing approval. Worker success, local checks, independent review,
hosted CI and live adapter validation establish different facts.

The acceptance helper evaluates recorded evidence; it does not manufacture
missing proof or grant project acceptance. Synthetic fixtures cannot certify
live behavior. The Governor reports a governed project's technical readiness
separately from the owner authorization, bound to candidate, tree and scope, that
its merge, release or deployment needs; project governance makes that decision.

Report the original objective, achieved or blocked criteria, candidate/check
evidence, material route exceptions, uncertainty and remaining gates. Keep
unobserved quota, usage and cost unknown. Name unresolved native references and
the next safe action without copying Orca's lifecycle into Pod records.

For candidate preparation, remote validation, evidence reuse and action
recovery, use the Governor reference. Project governance retains merge, release
and deployment authority.
