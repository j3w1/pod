# Planning

Map criteria, delivery, dependencies and required audits with provenance and checks. Bind trusted audit rules at intake as cited `project_policy` assurances, never optional model constraints, with scope, question, candidate, existing proof and insufficiency. Record each delivery unit's audit with the assurance's `unit` field. Trivial direct work needs no map. Keep one coordinator-held active obligation; unfinished work needs action, an external block or controlling wait, reconsidered when resolved.

Before isolated implementation, reuse the objective worktree and its branch or explicitly request `--branch orca/<task-slug>`; bind repository/common-dir, branch and path; display labels prove nothing. Preserve unrelated work. Concurrent writers use per-assignment `placement` worktrees and merge ancestry; settle shared contracts before overlapping edits.

Fix governance paths at intake: canonical project policy, `.pod/config.yaml`, tracked root `AGENTS.md`/`CLAUDE.md`, subject to direct-user exclusions. Adopting proposals requires direct user revision or cited policy. Initial target snapshots are trusted; Git cannot prove authorship. Candidate-containing governance updates need exact-snapshot user authority. Reconcile base changes before admission/effects, retaining ids/history/cited text; withdraw only genuinely gone policy. Unavailable sources hold work.

Optimize time to a verified result. At transitions dispatch ready distinct work that shortens that path; waiting is valid, spare capacity creates no duty, lean is no one-worker rule.

Packets name outcome, done-when (verification to perform/fix), served obligations, boundary/actions, candidate, route, digested sources and report format. Investigations name decision and stop condition. Include no secrets or whole issue/conversation; future outputs belong in scope, not sources. Preserve discarded results/branches; disposition satisfies nothing.

Corrections use direct/delegation judgment and current pool/pin. Retain findings; briefs identify failed rule, alternate entrypoints, supported records and status/wait consumers. Diagnose repeats with example, hypothesis and discriminating check. For recurring delta-review defects, state one predicate and cover sibling states in one table test.

A `receipt_limit` or retained-history `finding_limit` refusal first names any pending admission whose report must be consumed. Settle its exact native work and consume that report before retrying. If a worker failed without a verdict, record a truthful failed or blocked observation through the ordinary report path; it supplies no passing proof. Only when no report is pending does the refusal give the next checkpoint's `renew` request. Read the map's `next_seq`, replace the fresh-id placeholder, and use the supplied state fields with that `seq`. An active coordinator replacement is valid only when the coordinator slot is free; when another row holds it, use `state: "waiting", wait: {class: "sequenced", referent: HOLDER}`. A blocked replacement can supply its matching `external`. Omit state fields only when OLD is non-terminal and its existing state can continue. This is an identical mechanical renewal for every kind and provenance, with no owner question or revision. Supply no check, source, boundary or other definition fields: changing those uses the existing revision authority. OLD stays frozen as renewed history, with policy citations still following governance adoption; NEW carries the definition and accepted criterion mapping, has no proof, and needs fresh evidence. Physical parents and frozen admission bindings remain recorded; effective links and waits follow the new tip. New unrelated children name that tip.

Settle and consume every serving review or investigation before renewal; dispositions apply only to implementation results. Assurance admission reserves one receipt and 32 findings per pending serving attempt, including the new one, within each 64-record bound. An admission that cannot reserve these slots names the pending report to consume, or the exact renewal request when none is pending. Native settlement does not release a reservation until consumption, and ordinary checkpoint receipts cannot use those slots. A recorded route mismatch does not release a reservation: a review Pod keeps refusing for route mismatch holds its slots, and its objective already waits on the route decision. For a large map, use small `update` patches and bounded triage groups within the discovered input and row limits; terminal rows may be omitted and remain in history. A count-legal request can still exceed the byte limit.
