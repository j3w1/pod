# Pod v0.2.0

The governor becomes a kernel. The lean governor is not replaced beside a second
one; it is evolved in place, and its conservative rules become the innermost layer
of the new decision — authorization and correctness first, efficiency only after.

- **`ALLOW` / `REUSE` / `DEFER`.** `WARN` stops being a decision and becomes an
  annotation on one, because a warning tells you something about an action; it does
  not ambiguously answer whether the action should run. Where the lean governor said
  "don't start another one", the kernel says the useful result is already here: it
  attaches to the run in flight or reads back the evidence already recorded.
- **Delivery units and candidate generations.** A candidate is no longer a commit
  but a frozen identity — commit, tree, base, workflow digests, verification
  definition, environment and policy revision — observed from Git rather than
  supplied by the caller. Every journalled row binds its own commit, so a superseded
  generation is read back by that commit and never by the unit's current one, and
  two independent units converge without blocking each other.
- **Local preflight** gates remote validation, and a push that triggers CI journals
  the validation it starts, so a later dispatch attaches to that run instead of
  doubling it.
- **Managed execution.** Admission and effect happen in one transaction: an
  intention is journalled before the external call, and a lost answer becomes an
  `UNKNOWN` row that only reconciliation settles from provider readback. Nothing is
  resubmitted on the strength of not having heard back.
- **Failure classification** routes a repeated remote failure through the existing
  intervention ledger rather than a second anti-thrashing counter, and supersedence
  cancels only a pending, cancel-safe validation.
- **Migration is deliberate.** A `pod-governor/v1` journal is carried forward in
  place, but its rows are marked and never promoted to v2 proof: the upgrade cannot
  supply the binding v1 never froze, so such a row is history rather than evidence.

Every rule the lean governor enforced has a passing test in the new suite. `gh`
behaviour against a real repository, required-check reporting and merge-queue
semantics remain `NOT_RUN`; see `docs/validation.md`.
